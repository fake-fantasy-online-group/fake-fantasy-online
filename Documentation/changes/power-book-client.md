# 威能录客户端

## Interaction

The inventory header exposes 威能录 only after the server advertises `hello.result.powerBook = "1"`. Opening the panel requests read-only inventory and unlocked-record data. Select a recorded power and an unlocked bag darkgold item, then press 刻印威能 once. No additional confirmation, material, currency, or new native opcode is introduced. Existing permanent equipment effects are not automatically updated when the recorded roll improves.

The server remains authoritative for profession, source-level and slot eligibility. The client rejects worn, locked, non-legendary, stale or unmatched-native targets. It displays the server's normal `名称：效果` description including actual effect ranges, rather than inventing a power-score format or calculating combat values.

## Data and recovery

- `powerbook.list`: immutable request ID and decimal offset; response carries `powers`, `revision`, `nextCursor`. Each response contains at most 50 records. Cursor progression, duplicate IDs and revision coherence are checked before publishing a page.
- `powerbook.imprint`: immutable request ID, observed revision, target UID and power ID. It uses the existing single pending mutation and character-scoped retry journal. Success is `powerbook.result`; failure is `powerbook.imprint`.
- A submitted action never changes item state locally. Only server inventory snapshots publish the result. A successful receipt triggers one read refresh, not a second mutation.
- Close/Cancel, repeated clicks, delayed pages, failed transport, stale revisions, lost reads and session resets do not resend writes or change the selected request payload. Read timeout releases the read after 15 seconds for manual retry.
- Collection scope and record semantics are server-owned. Pure mechanical powers may carry zero numeric roll and are displayed without a fabricated range.
